# Идея: строка-заголовок в «🚫 В СПАМ» должна показывать результат проверки

Дата: 2026-11-17. Статус: **сделано в тот же день** (`SpamDesk._headline()` в `app/views.py`, тест
`test_desk_headline_shows_check_result`). Ниже — исходное описание идеи.

## Сейчас

Бот отвечает на присланный адрес или домен сообщением, которое начинается со строки
`🚫 В СПАМ — проверил.`

Дальше идут блоки «Добавлю в спам-фильтр (N)», «Уже в спаме», «🛑 Свои домены»,
«⚠️ Защита от случайности». Сама первая строка ничего не говорит: «проверил», а что нашёл — непонятно.
Результат приходится вычитывать из блоков ниже.

## Хочется

Чтобы в первой строке был итог проверки по базе: есть ли уже эта сущность (адрес или домен) в спам-фильтре,
сколько новых, сколько дублей, сколько защищено.

Черновик формата (согласовать перед правкой):

- `🚫 В СПАМ — новых: 1, уже в спаме: 0`
- `🚫 В СПАМ — всё уже в спаме (2)`
- `🚫 В СПАМ — новых: 2, уже в спаме: 1, защищено: 1`
- Если среди присланного есть свои домены, добавить `свои: N`.

Для одиночного адреса можно проще: `🚫 В СПАМ — hazel@example.com: новый, в фильтре его ещё нет` /
`… уже в спам-фильтре`.

## Где править

- `app/views.py`, класс `SpamDesk`, метод `request()`: заголовок `lines = ["🚫 В СПАМ — проверил."]`.
  Счётчики уже есть в `groups` (`ok` / `dup` / `warn` / `own`), строка собирается после цикла классификации.
- Тест: `tests/test_manual_spam.py` (проверки текста ответа `desk.request(...)`).

## Заметки

- Итоговое сообщение после «ОК» (`SpamDesk.decide()`) выглядит иначе: «✅ В спам-фильтре (N)». Заодно можно
  выровнять формулировки, чтобы подтверждение и итог читались одинаково.
- Текст бота меняется на сервере только через git: правка локально, push, pull, пересборка контейнера `mail-bot`.
