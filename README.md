# mail-sorter

Серверная сортировка почты по правилам для IMAP-ящиков, у которых нет своих серверных фильтров (Sieve).

Типичный случай — почта на shared-хостинге: фильтры там либо работают только в веб-интерфейсе, либо их нет вовсе, а правила Outlook / Thunderbird срабатывают, только пока программа открыта на компьютере. `mail-sorter` крутится 24/7 в Docker-контейнере на VPS, сам ходит в ящики по IMAP и раскладывает письма прямо на сервере — результат сразу виден на всех устройствах.

## Что умеет

- Правила на ящик: по точному адресу отправителя, по домену, по подстроке в теме.
- Действия: перенести в папку (создаётся автоматически), пометить прочитанным.
- Проход **по всем папкам ящика** — и при старте, и в каждом цикле (по умолчанию раз в 60 с). Корзина, спам, черновики и сами папки назначения не трогаются.
- Точная проверка отправителя: сервер ищет кандидатов, а решение принимается по разобранному заголовку `From`, чтобы `xuser@mail.ru` не совпал с `user@mail.ru`.
- Кириллица в именах папок (modified UTF-7).
- Логи в stdout (`docker logs`) и в файл с ротацией.
- Уведомления о сбоях на e-mail с ограничением частоты, письмо о восстановлении.
- Docker: отдельный контейнер, `restart: unless-stopped`, healthcheck по heartbeat, лимит памяти 128 МБ, непривилегированный пользователь.

## Структура

```
app/
  main.py         цикл обхода ящиков, логирование, сигналы
  sorter.py       работа с IMAP: поиск, проверка правил, перенос
  config.py       настройки из env, загрузка и валидация правил
  notifier.py     уведомления о сбоях по SMTP
  imap_utf7.py    кодирование имён папок
  healthcheck.py  проверка для Docker HEALTHCHECK
tests/            pytest
```

## Настройка

Секреты и персональные данные в репозитории не хранятся:

| Файл | Что внутри | В git |
|---|---|---|
| `.env` | ящики и пароли, хосты, адрес для уведомлений | нет |
| `rules.yaml` | правила (адреса контрагентов) | нет |
| `.env.example`, `rules.example.yaml` | шаблоны | да |

```bash
cp .env.example .env            # заполнить MAILBOXES и остальное
cp rules.example.yaml rules.yaml
chmod 600 .env rules.yaml
```

`MAILBOXES` — JSON-словарь в одну строку: `{"box@domain.ru": "пароль", ...}`. Правила работают только для ящиков, которые есть в `MAILBOXES`.

## Запуск

```bash
mkdir -p data && chown 10001 data   # контейнер работает не от root
docker compose up -d --build
docker compose logs -f
```

После изменения `rules.yaml` или `.env`: `docker compose restart` (для `.env` — `docker compose up -d`).

## Ограничения

- Если сервер не поддерживает `MOVE`, перенос делается через `COPY` + `\Deleted` + `EXPUNGE`. Без `UIDPLUS` команда `EXPUNGE` удаляет из папки все письма с флагом `\Deleted` — как и у большинства почтовых клиентов.
- Пароли ящиков хранятся на сервере в `.env` — держите доступ к VPS закрытым (SSH по ключу, права 600 на файл).
