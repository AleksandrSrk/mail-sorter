# mail-sorter

Серверная сортировка почты по правилам для IMAP-ящиков, у которых нет своих серверных фильтров (Sieve), плюс общий спам-фильтр с обучением, автоматической отпиской от рассылок и Telegram-ботом для управления.

Типичный случай — почта на shared-хостинге: фильтры там либо работают только в веб-интерфейсе, либо их нет вовсе, а правила Outlook / Thunderbird срабатывают, только пока программа открыта на компьютере. `mail-sorter` крутится 24/7 в Docker на VPS, сам ходит в ящики по IMAP и раскладывает письма прямо на сервере — результат сразу виден на всех устройствах.

## Что умеет

- **Правила в SQLite-базе.** Правило — это ящик (или все ящики сразу), папка назначения, «пометить прочитанным» и список условий: точные адреса, домены, подстроки в теме, серверная метка спама (`X-Spam-Flag` / `X-Spam-Status: yes`). Правила перечитываются каждый цикл — правки применяются без перезапуска.
- **Общий спам-фильтр для всех ящиков.** Правило с флагом `learn` — цель обучения.
- **Обучение.** Отправитель письма, которое пользователь сам перетащил в папку спама (с любого устройства), попадает в фильтр всех ящиков. Письма, перенесённые туда самим сервисом, в обучение не идут. Собственные домены спамом не считаются никогда.
- **Отписка от рассылок** по заголовку `List-Unsubscribe` (RFC 2369 / RFC 8058) — только для писем, которые пользователь кинул в спам сам:
  - `mailto:` — письмо на адрес отписки с того ящика, куда пришла рассылка;
  - `https:` — один `POST List-Unsubscribe=One-Click`, только если отправитель заявил поддержку one-click; без редиректов, внутренние адреса запрещены. Ссылки из текста письма и страницы отписки не открываются.

  После отписки адрес остаётся в фильтре; если от него неделю (`UNSUB_QUIET_DAYS`) нет писем — снимается с фильтра в список отписанных, и дальнейшие письма (например, полезные уведомления) снова доходят. Если пользователь снова кинет такое письмо в спам — адрес возвращается в фильтр навсегда, повторной отписки нет.
- **Telegram-бот** (только для владельца): списки спам-адресов и доменов с кнопками «убрать из фильтра», «скрыть», «блокировать весь домен»; скрытые; история отписок. Подозрительно полезные адреса — наверху с пометкой (мы им писали, писали на их домен). Бесплатные почтовые домены целиком заблокировать нельзя.
- **Уведомления в Telegram**: ошибки (с ограничением частоты), восстановление, отписки.
- **Инкрементальный обход**: для каждой папки запоминаются `UIDVALIDITY` и последний обработанный UID, в цикле читаются заголовки только новых писем. Полный проход — при старте и раз в сутки ночью (`FULL_SCAN_HOUR`). Корзина, спам, черновики и папки назначения не трогаются.
- Точная проверка отправителя по разобранному `From`, кириллица в именах папок (modified UTF-7), логи в stdout и файл с ротацией.
- Docker: два контейнера (сортировщик и бот) на одном образе, `restart: unless-stopped`, healthcheck по heartbeat, лимит памяти, непривилегированный пользователь.

## Структура

```
app/
  main.py         цикл обхода ящиков, очередь отписок, логирование
  sorter.py       IMAP: новые письма, проверка правил, перенос, обучение, сбор адресатов из «Отправленных»
  db.py           SQLite: правила, списки и их статусы, отписки, контакты; первичный перенос из rules.yaml
  unsub.py        отписка по List-Unsubscribe
  bot.py          Telegram-бот
  views.py        экраны и действия бота (без Telegram — тестируется отдельно)
  scoring.py      оценка «полезности» адресов и доменов
  notifier.py     уведомления в Telegram
  state.py        закладки инкрементального обхода
  config.py       настройки из env, модель правила
  imap_utf7.py    кодирование имён папок
  healthcheck.py  проверка для Docker HEALTHCHECK
tests/            pytest
```

## Настройка

Секреты и персональные данные в репозитории не хранятся:

| Файл | Что внутри | В git |
|---|---|---|
| `.env` | ящики и пароли, хосты, токен бота, ID владельца | нет |
| `rules.yaml` | стартовые правила — переносятся в базу один раз | нет |
| `data/` | база `mail.db`, состояние обхода, логи | нет |
| `.env.example`, `rules.example.yaml` | шаблоны | да |

```bash
cp .env.example .env              # заполнить MAILBOXES, TG_BOT_TOKEN, TG_ADMIN_ID
cp rules.example.yaml rules.yaml  # стартовые правила (необязательно)
chmod 600 .env rules.yaml
```

`MAILBOXES` — JSON-словарь в одну строку: `{"box@domain.ru": "пароль", ...}`. Обрабатываются все ящики из `MAILBOXES`.

При первом запуске правила из `rules.yaml` (и старый `data/learned_spam.txt`, если есть) переносятся в `data/mail.db`; дальше источник правды — база.

## Запуск

```bash
mkdir -p data && chown 10001 data   # контейнеры работают не от root
docker compose up -d --build
docker compose logs -f
```

Бот: написать ему `/start` с аккаунта `TG_ADMIN_ID`. Остальным он не отвечает.

## Тесты

```bash
pip install -r requirements.txt pytest
python -m pytest -q
```

## Ограничения

- Если сервер не поддерживает `MOVE`, перенос делается через `COPY` + `\Deleted` + `EXPUNGE`. Без `UIDPLUS` команда `EXPUNGE` удаляет из папки все письма с флагом `\Deleted` — как и у большинства почтовых клиентов.
- Отписка работает только при наличии `List-Unsubscribe`; часть отправителей отписку игнорирует — поэтому адрес остаётся в фильтре до недели тишины.
- Пароли ящиков и токен бота хранятся на сервере в `.env` — держите доступ к VPS закрытым (SSH по ключу, права 600 на файл).
